# 技術検討

## 実現可能性

| 項目 | ハッカソンでの実現性 | 方針 |
| --- | --- | --- |
| 地図・自販機位置 | 高い | 対象施設の機械を事前登録し、Leafletで表示 |
| 商品別のリアルタイム在庫 | 低い | 「在庫」ではなく、時刻付きの観測状態として扱う |
| 欠品投稿 | 高い | 機械・商品・状態・観測時刻だけを必須にする |
| 近隣代替機の案内 | 高い | 商品状態と距離で絞り込む |
| 需要分析 | 中程度 | 欠品投稿の集計から開始し、販売・補充データは後で結合 |
| AI補充提案 | 中程度 | MVPはルールベース。学習データ獲得後に予測へ移行 |
| 写真商品認識 | 中〜低 | 誤認識とSKU更新が重いため、MVPでは証跡保存のみ |

## 現在のデモ構成

```text
React UI
  ├─ Leaflet / OpenStreetMap（地図）
  ├─ demo.ts（自販機・商品・初期観測）
  ├─ localStorage（ユーザーのデモ投稿・買えなかった体験）
  └─ domain.ts
       ├─ 30分以内の投稿を優先
       ├─ 在庫ありの近隣候補を距離順に選択
       └─ 欠品投稿を補充優先度・潜在売上に変換
```

バックエンドなしで審査員の端末上でも体験できる。写真は端末内プレビューのみで外部送信せず、解析結果は登録済みサンプルから生成する。画面上では必ず「AI解析モック」「デモデータ」と明記し、実在庫と誤認されないようにする。

公開は Cloudflare Workers Static Assets を使う。D1/R2/Workers AIは作成せず、費用と障害点を増やさない。

## 実証実験用のCloudflare構成

```text
Cloudflare Worker + Web/PWA
  │
  ├── 匿名セッション + Turnstile（任意）
  ├── D1（自販機・商品・観測・買えなかった体験）
  ├── R2（投稿写真）
  └── Workers AI（画像から商品・状態候補を構造化）
        ├─ 投稿頻度制限
        ├─ 状態の信頼度計算
        └─ 集計・通知
```

既存の `supabase/migrations/202608260001_initial.sql` は、PostGISを使う代替案として残している。Cloudflareへ寄せる場合はD1で緯度経度を保持し、対象施設内の少数自販機をアプリ側で距離順に並べれば十分。規模拡大時に専用の地理検索を再検討する。

## 状態と信頼度

状態は「真の在庫」ではなく観測値。表示時は次の優先順位とする。

1. 連携済みベンダー在庫（取得時刻つき）
2. 30分以内に複数ユーザーが一致した投稿
3. 30分以内の単一ユーザー投稿
4. それ以前の観測は「未確認」へ減衰

現在のデモは理解しやすさを優先し、30分以内の最新投稿1件を採用する。本番では `source_weight × time_decay × agreement` で信頼度を算出し、「78%・12分前」のように表示する。

## 近隣候補のロジック

MVPは次で十分。

1. 選択商品を扱う自販機だけを対象
2. 最新状態が `available` のものだけを対象
3. 現在地からの直線距離で昇順
4. 最も近い1〜3件を提示

実証段階では営業時間、館内階層、通行可能な経路、状態信頼度をスコアへ加える。屋内ではGPSが不安定なため、QRコードまたは施設内ゾーンIDで機械を特定する方が堅い。

## 需要分析の注意

欠品投稿数は、そのまま逸失販売数ではない。投稿者の偏り、重複、代替購入を含むため、現在の65%はデモ用仮説にすぎない。実証では次のデータで校正する。

- 自販機別・SKU別の販売数
- 補充時刻と補充本数
- イベント来場者数・時間帯
- 天候・気温
- 欠品投稿後に代替機を開いたか

個人単位の購買過程予測はMVPに不要。まず匿名の集計値で補充判断に寄与するかを確認する。

## 2日間の実装順

### Day 1

- 午前: 対象施設・商品を固定、データ投入、地図と商品選択
- 午後: 投稿、鮮度、代替候補、モバイル表示
- 夕方: Supabase接続またはローカルフォールバック

### Day 2

- 午前: ベンダー集計画面、指標の仮説を明記
- 午後: QR導線、デモシナリオ、実機QA
- 発表前: オフライン用スクリーンショット／録画、障害時のデモデータ復元

## 運用・法務上の注意

- OpenStreetMap標準タイルはSLAがなく、大量アクセスやプリフェッチは禁止されている。本番では専用プロバイダーを使う。
- 投稿写真には顔、位置情報、周辺人物が入り得る。MVPでは写真必須にしない。
- 自販機の設置位置や商品情報を公開する権利を施設・ベンダーと確認する。
- 金銭価値のある報酬を導入する前に、不正対策、利用規約、個人情報、会計処理を確認する。
